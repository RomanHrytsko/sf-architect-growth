## Принципи

- Глибина замість швидкості. Тема закрита, коли можу: пояснити, реалізувати з тестами, записати ADR з альтернативами, назвати 2 ситуації, де рішення — помилка.
- Спочатку «чому», потім «як». Повернення до власного коду щокварталу.
- Пропущений тиждень не надолужуємо — план зсувається.
- AI — спаринг-партнер; перше рішення за Романом.

## Фази

Кожна фаза: 11 тижнів навчання, 1 тиждень ретро, 1 буфер.

### Фаза 1 · 9.11.2026 – 7.02.2027 · Clean Code, тести, enterprise-патерни
- Т1: baseline (репо, CI, PMD; само-ревʼю старого коду за рубрикою)
- Т2–4: Clean Code в Apex і LWC (імена, SRP, побічні ефекти, помилки); 3 каті з рефакторингом
- Т5–7: тестування (піраміда, Stub API, test data builders, bulk-тести, Jest)
- Т8–10: Selector, Domain, Service, Unit of Work; trigger framework; Strategy і Factory через Custom Metadata
- Т11: RenewalHub v0.1 · Т12: ретро · Т13: буфер
- **Gate:** v0.1 з тестами, 0 critical у PMD, ≥ 5 ADR, 3 каті, середня оцінка PR ≥ 3.0

### Фаза 2 · 8.02 – 9.05.2027 · Дані, доступ, інтеграції
- Модель даних: LDV, data skew, селективні запити, big objects чи Data Cloud
- Sharing і безпека: OWD, sharing rules, Apex managed sharing, FLS/CRUD, with/without sharing
- Асинхронність і події: Queueable, Batch, Platform Events, CDC, Pub/Sub API; ідемпотентність, порядок, повтори
- Інтеграції: External Credentials, anti-corruption layer, outbox, saga; mock-білінг (проєкт IntegrationHub)
- LWC-архітектура; Flow проти Apex як окрема тема ADR
- **Gate:** RenewalHub v0.5 з event-driven інтеграцією і моделлю доступу, ≥ 8 ADR, 1 design-review, IntegrationHub у стані portfolio-ready

### Фаза 3 · 10.05 – 8.08.2027 · Agentforce та AI-архітектура
- Анатомія агента: topics, instructions, actions; коли агент, а коли Flow чи Apex
- Actions як контракти: типізовані invocable-методи, ідемпотентність, prompt templates
- Grounding: Data Cloud, knowledge, пошук з урахуванням прав
- Довіра й безпека: Trust Layer, running user, PII, prompt injection, threat model
- Eval: золотий набір кейсів, регресії, спостережуваність, вартість
- Зовнішні системи: Agent API, MCP
- Кожен реліз Salesforce: 1 година на release notes і корекція плану
- **Gate:** 2 агенти, eval ≥ 30 кейсів, ADR про межі автономії, threat model на 1 сторінку

### Фаза 4 · 9.08 – 7.11.2027 · Масштаб і синтез
- DevOps і lifecycle: unlocked packages, гілки, CI/CD, scratch orgs, стратегія релізів
- IAM: SSO, OAuth-потоки, JWT, external client apps, MFA
- Governance і масштаб: multi-org, логування, моніторинг, продуктивність, вартість володіння
- 2–3 сценарії у форматі review board (підготовка + презентація 30–45 хв, ментор — суддя)
- RenewalHub v1.0, портфоліо-README, одна публічна стаття чи доповідь
- **Gate:** v1.0, 15–20 ADR, 3 design-review, рішення щодо CTA і наступного року

## Тижневий ритм (4 год)

| Блок | Час | Що |
| --- | --- | --- |
| Learn | 1 год | Одне джерело на тему тижня; нотатка своїми словами в `notes/` |
| Practice | 1,5 год | Ката або інкремент RenewalHub, тести першими |
| Design | 0,5 год | ADR, діаграма, записані альтернативи |
| Review | 1 год | Само-ревʼю PR за рубрикою, журнал, 3 питання до ментора |

Раз на місяць design review замість Learn. Раз на квартал — ретро, оновлення плану, рефакторинг коду попереднього кварталу. Для 3 год прибрати Design, для 5 год додати годину на каті чи читання.

## Рубрика ревʼю (1–4)

Рівень 1 — працює на happy path; рівень 2 — акуратно, але без дизайну; нижче 3 доробляємо до merge.

| Критерій             | Рівень 3 (Senior)                                                               | Рівень 4 (Architect)                                        |
| -------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Коректність і ліміти | Bulk-safe, без SOQL/DML у циклах, крайові випадки в тестах                      | Рішення витримує 10× обсяг, межі лімітів задокументовані    |
| Дизайн               | Одна відповідальність на клас, низьке зачеплення, залежності вказують усередину | Шви розширення обрані свідомо, немає передчасної абстракції |
| Тестованість         | Unit-тести без бази даних там, де можна; тести перевіряють поведінку            | Тести переживають рефакторинг без змін                      |
| Безпека              | CRUD/FLS і sharing обрані свідомо та пояснені                                   | Є коротка threat model для зміни                            |
| Читабельність        | Імена розкривають намір, функції короткі, коментарі пояснюють «чому»            | Новачок розуміє модуль без пояснень                         |
| Рішення              | Є ADR з альтернативами                                                          | ADR називає атрибути якості, ризики й тригери перегляду     |

Цільова середня оцінка: ≥ 3.0 до кінця фази 1, ≥ 3.3 до кінця фази 2, ≥ 3.5 до кінця року. Пороги переглянемо після перших трьох оцінених PR.
